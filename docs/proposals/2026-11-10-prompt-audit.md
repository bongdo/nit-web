# Аудит базового промта по истории чатов

Дата: 2026-11-10.
Источник: `~/.local/share/opencode/opencode.db`.
Охват: 216 сессий, из них 124 корневых и 80 субагентских; 333 непустых хода пользователя
в корневых сессиях. Субагентские сессии в подсчёт «движений пользователя» не входят.

Метод: SQL по `session_message` / `session_v2`, эвристики по текстам и вызовам
инструментов. Цифры приблизительные: один и тот же смысл может быть посчитан дважды,
если сформулирован по-разному.

## Главное

Промт хорошо задаёт *как писать код* и *как отчитываться*. Он почти не задаёт
*как доводить работу до пользователя*: выкатить, показать URL, назвать секрет,
не останавливаться на середине. Поэтому пользователь вручную закрывает эти дыры
в чате, и эти просьбы повторяются.

## Проблемы самого промта

### 1. Устаревший «единственный интерфейс проекта»

В `~/.config/opencode/AGENTS.md`:

> Единственный интерфейс проекта: `check`, `run`, `db`, `spec`, `shots`.

В `nit-gui/bin` лежат `check`, `run`, `deploy`, `nixos`, `frankfurt`, `drop`,
`auth`, `funnel`, `gigaam`, `languagetool`. Команд `db`, `spec`, `shots` нет.
`bootstrap` создаёт `bin/shots` только при наличии `scripts/pty-smoke.sh`, которого
здесь нет.

Агент один раз попробовал `bin/shots` и получил ошибку. Это прямая трата хода и
повод выдумывать команды.

### 2. Нет закрывающего цикла

`bin/check` — оракул. `save` — обязанность агента. Деплой — нет.
В проекте `bin/deploy` уже печатает URL и делает health check, но промт не требует
вызывать его после правки. Пользователь видит старую сборку и присылает тот же баг
второй раз.

### 3. Секреты

`bin/auth` генерирует 24 символа, печатает их в stdout и сохраняет только хеш.
Если агент провернул ротацию и не пересказал пароль, пользователь заперт снаружи.
В промте про секреты нет ни строки.

### 4. Дубли и расхождения слоёв

Правила живут в четырёх местах:

- `~/.config/opencode/AGENTS.md` — общий канон;
- `AGENTS.md` проекта — команды и drop;
- `opencode.jsonc` — системные промты агентов (`independent`, `evaluator`, …);
- `.agent/prompt` — промт loop-исполнителя.

Они уже расходятся: `.agent/prompt` требует `tasks done`, а агент `independent`
в `opencode.jsonc` запрещает `tasks done`. Если сессия получит не тот промт,
поведение будет противоположным. Это не обязательно баг, но два источника правил
надо держать в голове.

### 5. Ponytail трижды

Плагин даёт системный reminder, глобальный `AGENTS.md` даёт раздел, скилл даёт
полный текст. На каждую сессию это повторение. Пока не мешает, но контекст ест.

### 6. Глобальное правило про HTML

Правило «HTML-фрагмент в блоке `html`, nit-gui показывает превью» записано глобально.
В pero, term и CLI-сессиях такого рендера нет. Стоит оговорить: если клиент не
умеет превью, отдавай markdown.

## Предлагаемый патч

### `~/.config/opencode/AGENTS.md`

```diff
 ## Вход в проект
 - Сначала прочитай `.envrc` и `bin/`. Не угадывай команды сборки и тестов.
-- Единственный интерфейс проекта: `check`, `run`, `db`, `spec`, `shots`.
-  Они попадают в PATH через direnv.
-- Нет `bin/check` — создай через `bootstrap` и покажи, что он проверяет.
+- Интерфейс проекта — то, что лежит в `bin/`. Смотри его, не угадывай;
+  `check`, `run`, `db`, `shots` — только если они там есть.
+- Нет `bin/check` — создай через `bootstrap`.
+
+## Границы
+- Работай в директории сессии. Если это не проект (нет `.envrc` или `AGENTS.md`) —
+  не угадывай, скажи и спроси.
+- Секрет, который нужен пользователю (пароль, токен, URL с ключом), печатай в
+  ответе один раз. Ротацию без прямой просьбы не делай.
+- Дольше пары минут — одна строка: что делаешь и зачем.
+- Один запрос — весь результат. Не заканчивай планом или «продолжить?», если
+  следующий шаг обратим.
+- Независимые куски — субагентами параллельно; один файл — сам.
+- Дефект в общем компоненте — grep все вхождения и чини сразу все.
+- Вопросы: максимум 3, каждый самодостаточный, без «пункт 2».
```

Плюс к разделу «Проверка»:

```diff
 - Не пиши «готово», «работает», пока `bin/check` не зелёный. Не запускал — так и скажи.
+- Если проверка визуальная — дай URL и список того, что смотреть. Скриншота нет —
+  так и скажи.
```

### `AGENTS.md` проекта

```diff
-- After a green `bin/check` and a successful deploy, `save "<what changed>"`.
+- Cycle: green `bin/check` → `save "<what changed>"` → `bin/deploy` (nixos by
+  default; `frankfurt` for the public URL) → report the URL and what to look at.
+- A UI or behavior change is not done until it is deployed: the user sees the old
+  build until then.
+- If a deploy rotates a secret, print the new password in the reply.
```

## Не промт, но рядом

- Два форка и повторяющиеся одинаковые сообщения в них — поведение приложения,
  не модели.
- Вопросы агента иногда не появляются без перезагрузки страницы — это баг nit-gui,
  из-за него пользователь несколько раз писал «задай мне вопрос».
- Ask-режим вкладывает в сообщение `<repository-context>` на 17–24 тыс. символов
  (6 сообщений). Это не промт, но это контекст, который оплачивается каждый раз.

## Что проверить после правки

1. Новая сессия в `nit-gui`: правка UI → агент сам делает check, save, deploy,
   печатает URL.
2. Новая сессия в `/home/ubuntu` (не проект): агент не угадывает проект.
3. Ротация пароля: агент печатает новый пароль.
4. Запрос из 3 независимых кусков: агент запускает субагентов без напоминания.

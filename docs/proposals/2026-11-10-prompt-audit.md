# Аудит базового промта по истории чатов

Дата: 2026-11-10.
Источник: `~/.local/share/opencode/opencode.db`.
Охват: 216 сессий, из них 124 корневых и 80 субагентских; 333 непустых хода пользователя
в корневых сессиях. Субагентские сессии в подсчёт «движений пользователя» не входят.

Метод: SQL по `session_message` / `session_v2`, эвристики по текстам и вызовам
инструментов. Цифры приблизительные: один и тот же смысл может быть посчитан дважды,
если сформулирован по-разному.

## Главное

Промт хорошо задаёт *как писать код* и *как отчитываться*. Он почти не задаёт
*как доводить работу до пользователя*: выкатить, показать URL, назвать секрет,
не останавливаться на середине. И почти не задаёт *что показывать в ответе*:
картинку, таблицу или ссылку. Поэтому пользователь вручную закрывает эти дыры
в чате, и эти просьбы повторяются.

## Что умеет чат сейчас

| Формат | Поддержка | Детали |
|---|---|---|
| Markdown / GFM | да | `react-markdown` + `remark-gfm`: заголовки, списки, таблицы, task list, зачёркивание, автолинки |
| Код в fence | да, без подсветки | `CodeBlock` рисует `<pre><code>` без токенов, только кнопка Copy |
| `html` fence | да | живой iframe `srcdoc`, sandbox без `allow-same-origin`, auto-height |
| Mermaid | нет | в коде нет рендерера и зависимости; `vault/features/diagrams.md` пока черновик |
| Графики | только самодельные | inline SVG/canvas в `html`-блоке; внешние CDN и библиотеки не подключаются |
| Картинки и файлы | да | вложения и локальные ссылки через `AttachmentPreview` |

Практический вывод: архитектурную схему сейчас надо рисовать inline HTML блоками
и стрелками, а не mermaid. Богатый markdown работает, подсветки кода нет.

## Проблемы самого промта

### 1. Устаревший «единственный интерфейс проекта»

Было:

> Единственный интерфейс проекта: `check`, `run`, `db`, `spec`, `shots`.

В `nit-gui/bin` лежат `check`, `run`, `deploy`, `nixos`, `frankfurt`, `drop`,
`auth`, `funnel`, `gigaam`, `languagetool`. Команд `db`, `spec`, `shots` нет.
Агент один раз попробовал `bin/shots` и получил ошибку.

Исправлено: список больше не фиксируется в глобальном промте. Источник —
`bin/`, а проектный `AGENTS.md` агент обязан обновлять при расхождении.

### 2. Нет закрывающего цикла

`bin/check` — оракул. `save` — обязанность агента. Деплой — нет.
`bin/deploy` уже печатает URL и делает health check, но промт не требовал
вызывать его после правки. Пользователь видел старую сборку и присылал тот же баг
второй раз.

### 3. Секреты

`bin/auth` генерирует 24 символа, печатает их в stdout и сохраняет только хеш.
Если агент провернул ротацию и не пересказал пароль, пользователь заперт снаружи.

### 4. Не было правила отображения

Два указания конфликтовали: глобальное «визуализируй HTML-фрагментом» и проектное
«когда пользователь должен увидеть страницу — используй drop; не вставляй большой
HTML в чат». Агент выбирал ссылку там, где хватало inline-блока.

### 5. Дубли и расхождения слоёв

Правила живут в четырёх местах:

- `~/.config/opencode/AGENTS.md` — общий канон;
- `AGENTS.md` проекта — команды и drop;
- `opencode.jsonc` — системные промты агентов (`independent`, `evaluator`, …);
- `.agent/prompt` — промт loop-исполнителя.

Они расходятся: `.agent/prompt` требует `tasks done`, а агент `independent`
в `opencode.jsonc` запрещает `tasks done`. Если сессия получит не тот промт,
поведение будет противоположным. Это не обязательно баг, но два источника правил
надо держать в голове.

### 6. Ponytail трижды

Плагин даёт системный reminder, глобальный `AGENTS.md` даёт раздел, скилл даёт
полный текст. Пока не мешает, но контекст ест.

### 7. Правило про директорию

Проблема «старт не в том проекте» закрыта в приложении: 12 старых сессий стартовали
в `/home/ubuntu` или `/home/ubuntu/Projects`, сейчас сессия привязана к проекту.
В промт правило не добавляли.

## Что применено

### `~/.config/opencode/AGENTS.md`

- Визуализация по умолчанию — inline; ссылка только для полной страницы,
  приложения или файла на скачивание.
- Схема изменений — inline HTML; график — inline SVG/canvas без внешней библиотеки.
- Mermaid — только если клиент его реально рендерит.
- Интерфейс проекта — `bin/`; при расхождении с проектным `AGENTS.md` верить `bin/`
  и обновить список.
- Секрет печатать в ответе; ротацию без просьбы не делать.
- Прогресс раз в пару минут; не заканчивать планом, если шаг обратим.
- Просят «обсудим» — варианты, а не код.
- Независимые куски — субагентами; дефект — все вхождения.
- Вопросы: максимум 3, самодостаточные.
- Визуальная проверка — URL и список того, что смотреть.

### `AGENTS.md` проекта

- Цикл: green `bin/check` → `save` → `bin/deploy` → URL и что смотреть.
- UI-правка не сделана, пока не задеплоена.
- `bin/auth` при ротации: новый пароль печатать в ответе.
- `drop` — для полной страницы/приложения/скачивания; мелкая визуализация — inline.
- Список команд обновлять тем же изменением, если `bin/` изменился.

## Не промт, но рядом

- Два форка и повторяющиеся одинаковые сообщения в них — поведение приложения.
- Вопросы агента иногда не появляются без перезагрузки страницы — баг nit-gui,
  из-за него пользователь несколько раз писал «задай мне вопрос».
- Ask-режим вкладывает в сообщение `<repository-context>` на 17–24 тыс. символов
  (6 сообщений).
- Mermaid и подсветка кода в чате не реализованы. Это отдельная фича, не промт.

## Что проверить после правки

1. Правка UI → агент сам делает check, save, deploy, печатает URL.
2. Просьба «покажи схему» → inline `html`-блок, а не ссылка `drop`.
3. Полное приложение или файл на скачивание → ссылка `drop`.
4. Ротация пароля → агент печатает новый пароль.
5. Запрос из 3 независимых кусков → субагенты без напоминания.

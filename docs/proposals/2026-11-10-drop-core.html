drop: что улучшить в главной функции

Главная функция drop — «дал файл, получил ссылку». Сейчас каждое `drop <path>` создаёт новую публикацию, даже если ссылка та же. Ниже две правки, которые меняют модель, — их нужно выбрать до реализации. Анимации и прогресс загрузки уже сделаны и показаны в конце.

вопрос 1

Обновление на месте

Опубликовать новую сборку по старой ссылке, не плодя `app-2`, `app-3`.

drop ./dist → app → drop ./dist → app-2

Сегодня: новая папка, новый слаг, старые ссылки живут отдельно и копятся.

Предлагаю

  • Слаг — это адрес, а не файл. Повторная публикация с тем же слагом заменяет содержимое.
  • Версии по желанию. Старое содержимое остаётся в истории, откат — один клик.
  • Явный признак. В строке видно `v3` и дату, а не пять почти одинаковых строк.

Что решить

  • По умолчанию --slug app заменяет или требует --replace?
  • Сколько версий хранить: 3, 10 или только последнюю?
  • История — во всех публикациях или только для сайтов и сервисов?
# обновить app на месте
drop ./dist --slug app

# обновить и сохранить 3 версии
drop ./dist --slug app --history 3

# старое поведение: всегда новый адрес
drop ./dist --new
Почему это главное. Ссылка на drop живёт в чатах и заметках. Сейчас её нельзя обновить, не сломав или не раздвоив. Версии превращают drop из «свалки файлов» в адрес, на который можно ссылаться.

Нажмите «Обновить файлы»: версия растёт, адрес не меняется. «История» выключает хранение старых версий.
вопрос 2

Ссылка для шаринга

Отдать один drop человеку без аккаунта, не открывая его навсегда всему интернету.

private → public · двух состояний мало

Сегодня приватный drop видит только владелец cookie. Чтобы показать его коллеге, нужно нажать «public» — и он публичен навсегда.

Предлагаю

  • Подписанная ссылка с TTL (1 ч / 24 ч / 7 д) и отзывом.
  • Публичность не меняется. Шаринг — отдельный ключ, а не переключатель доступа.
  • Одна кнопка в строке: «Поделиться» → ссылка уже в буфере.

Что решить

  • Ссылка открывает весь drop или только выбранный файл?
  • Нужен ли лимит скачиваний и журнал «кто открывал»?
  • Максимальный TTL: 7 дней, 30 дней или «пока не отзовут»?
Цена. Токен в URL живёт в истории браузера и логах прокси. Подпись должна проверяться сервером, а не быть просто длинным слагом, иначе её нельзя отозвать.

Ссылка с доступом по времени

Любой, у кого есть ссылка, сможет открыть drop. Переключатель public не меняется.

https://frankfurt.tailf358cb.ts.net/nit/d/app/?t=k7Qm…
Ссылка отозвана. Открыть её больше нельзя.
В модели это третье состояние доступа: private (владелец), link (есть токен), public (все). Токен хранится хешем, как пароль.
